# 企业小程序销售记账系统一期设计文档

生成日期：2026-07-05

## 1. 设计目标

本期实现一个基于企业或个体工商户主体微信小程序的图书销售记账系统，核心解决：

- 订单来源可归属到具体销售方；
- 微信支付、邮寄、发货、退款状态可追踪；
- 销售返点和一层直接推荐奖励可计算、可溯源；
- 后台支持台账查看和 Excel 导出。

## 2. 总体架构

采用“一个 NestJS 单体后端 + 两个独立前端”：

- **后端** `src/server/`：Node.js + NestJS + TypeScript + MySQL，按业务领域划分 NestJS 模块。
- **微信小程序** `src/miniprogram/`：原生微信小程序，包含家长端和销售方端。
- **管理后台** `src/admin/`：Vue 3 + Element Plus + TypeScript，用于老板/管理员操作。

## 3. 技术栈

| 层 | 技术 |
|---|---|
| 后端框架 | NestJS 10 + TypeScript 5 |
| 数据库 | MySQL 8 + TypeORM |
| 小程序 | 微信原生小程序 |
| 管理后台 | Vue 3 + Element Plus + TypeScript |
| 导出 | SheetJS / exceljs |
| 对象存储 | 腾讯云 COS / 阿里云 OSS（可选） |
| 支付 | 微信支付 JSAPI |

## 4. 后端模块划分

每个模块包含 Controller、Service、Entity（TypeORM）和 DTO：

- `auth`：管理员登录、JWT、小程序 openid 获取；
- `sellers`：销售方 CRUD、上下级关系、seller_code 生成；
- `products`：产品配置、价格、售后天数、入群二维码；
- `qrcodes`：小程序码生成记录；
- `scan-logs`：扫码访问日志；
- `orders`：订单创建、状态、金额、来源；
- `payments`：微信支付下单、回调、幂等处理；
- `shipments`：发货信息、快递单号、售后观察期；
- `rewards`：返点规则、预计返点、最终返点、推荐奖励；
- `exports`：Excel 导出；
- `operation-logs`：关键后台操作日志。

## 5. 数据库核心表

### 5.1 用户与权限

- `admin_users`：管理员账号、密码哈希、角色、状态。

### 5.2 销售方与产品

- `sellers`：id、name、seller_code、parent_id、school、region、phone、status、remark、created_at、updated_at。
- `products`：id、name、cover、price、is_on_sale、default_quantity、aftersale_days、group_qrcode、intro、created_at、updated_at。
- `seller_qrcodes`：id、seller_id、product_id、image_url、created_at。

### 5.3 订单与支付

- `scan_logs`：id、seller_code、seller_id、product_id、openid、scene、ip、created_at。
- `orders`：id、order_no、product_id、seller_id、openid、quantity、unit_price、total_amount、status、paid_at、wx_transaction_id、created_at、updated_at。
- `order_addresses`：id、order_id、recipient、phone、province、city、district、address、remark、created_at。
- `payment_events`：id、order_no、raw_body、verified、amount、result、created_at。
- `shipments`：id、order_id、company、tracking_no、shipped_at、aftersale_start、aftersale_end、created_at。
- `refund_records`：id、order_id、amount、reason、operator、created_at。

### 5.4 返点与结算

- `reward_rules`：id、product_id、seller_id、rule_type、base_value、threshold、rate、fixed_amount、is_default、created_at、updated_at。
- `reward_records`：id、order_id、product_id、seller_id、beneficiary_id、reward_type、status、amount、rule_snapshot、formula、calculated_at、processed_amount、processed_at、remark。
- `operation_logs`：id、admin_id、action、target、detail、created_at。

## 6. 订单状态机

```text
pending_payment
  -> paid（支付回调成功）
  -> closed（超时关闭）
  -> cancelled（后台取消）

paid
  -> address_pending（已支付，待填地址）
  -> refunded（已退款）

address_pending
  -> shipping_pending（已填地址）

shipping_pending
  -> shipped（已发货）

shipped
  -> aftersale_waiting（进入售后观察期）

aftersale_waiting
  -> settlement_ready（售后观察期结束且未退款）
  -> refunded（已退款）
```

## 7. 返点状态机

```text
estimated（支付成功后生成预计返点）
  -> ready（售后观察期结束且未退款）
  -> pending（老板确认可处理）
  -> processed（已处理）
  -> reversed（已冲正）
  -> void（不处理）
```

## 8. 核心数据流

### 8.1 扫码购买主链路

1. 家长扫描销售方二维码，进入小程序产品页，URL 携带 `seller_code` 和 `product_id`。
2. 小程序记录扫码日志，只用于统计，不参与返点。
3. 小程序静默获取用户 `openid`。
4. 家长点击购买，小程序调用后端创建订单，后端校验 seller_code 和产品状态。
5. 后端调用微信支付统一下单，返回预支付参数。
6. 小程序调起微信支付。
7. 微信支付回调后端，后端验签、校验金额、幂等更新订单状态为 `paid`。
8. 支付成功后生成预计返点记录。
9. 家长填写邮寄地址，订单状态变为 `shipping_pending`。
10. 展示入群二维码。
11. 老板后台发货，填写快递公司和单号，订单状态变为 `shipped`，并进入 `aftersale_waiting`。
12. 售后观察期结束（发货时间 + 7 天）且未退款，订单变为 `settlement_ready`，生成最终返点。
13. 如果存在上级销售方，同时生成一层直接推荐奖励。

### 8.2 返点计算

- 基础返点：按每本固定金额或按实收金额比例。
- 阶梯返点：按销售方累计销量达到不同门槛后适用不同比例。
- 推荐奖励：订单可结算时，给直接上级销售方生成一笔奖励。
- 所有返点记录保存规则快照、公式、档位、计算时间，支持溯源。

## 9. 错误处理与幂等

- 微信支付回调：通过 `out_trade_no` 和 `transaction_id` 去重，使用数据库唯一约束或分布式锁。
- 同一订单只生成一组预计返点，通过 order_id + reward_type 唯一约束。
- 同一订单只生成一组最终返点。
- 已退款订单不生成最终返点；已生成最终返点后退款，生成冲正记录。
- 金额不一致时拒绝更新并记录异常支付事件。

## 10. 安全要求

- 支付密钥、API 证书、数据库密码等配置存放在 `.env` 文件，不提交到代码仓库。
- 管理员接口使用 JWT 认证。
- 小程序端只保存 `openid` 等必要信息，不暴露敏感配置。
- 前台文案避免“分销、返利、拉人赚钱”等高风险表达，使用“销售统计、参考返点、销售管理关系”。

## 11. 测试策略

- 单元测试：返点计算、订单状态机、 seller_code 生成。
- 集成测试：支付回调幂等、订单创建、发货与售后观察期流转。
- 端到端测试：扫码 -> 产品页 -> 下单 -> 地址 -> 发货 -> 返点。
- 数据核对测试：订单金额、销售汇总、返点明细、Excel 导出一致性。

## 12. 部署与配置

- 开发环境使用本地 MySQL 和 npm 运行。
- 生产环境使用 HTTPS 域名、微信支付回调地址配置正确。
- 提供 `.env.example` 说明所需环境变量。
- 提供数据库迁移脚本（TypeORM migrations）。

## 13. 一期范围

包含：

- 企业小程序基础框架；
- 家长端产品页、支付、地址、入群引导；
- 销售方端登录、数据查看、二维码展示；
- 管理后台：销售方、产品、订单、发货、返点、导出；

- 一层直接推荐奖励；

- 操作日志。

- 支付宝/聚合支付；
- 购物车与完整商城；
- 自动退款与自动打款；

- 物流自动查询；
- 优惠券与会员体系。
